## 1. 目标与范围
<!-- ≤8 行：做什么；输入 / 输出、目标硬件与形状；验收（性能对照谁、精度参考谁）；不做什么。 -->
在 MI308X（gfx942）上提供 MXFP4 routed（可带 FP8 逐行 shared expert）的两阶段 FlyDSL MoE，主目标是 DeepSeek-V4.1-Flash 整层。
- 入口：`prepare_moe_a8w4_ptpc_weight`（加载时转私有布局，可带 shared）与 `flydsl_moe_a8w4_ptpc`（bf16 进出）；`aiter.fused_moe` 认标记转调。
- 整层形状：主干 / MTP（E384 / 128 + shared，topk 6 / 3 + 1）× TP4 / TP8（I576 / 288→320），H5120，swiglu_limit 10。
- routed-only 形状（原 85 例）：Qwen3.8-Flash-Next TP2 / TP4、MiMo-V2.6-Flash TP8 / TP4、DeepSeek-V4.1-Flash TP4。
- 性能验收：整层 73 例逐例 ≤ min(1.02× 融合 FP8 PTPC, A8W4 split)，原 158 例逐例 ≤ 起点 moe-a8w4-shared-M6 × 1.02；新增 22 例只查回退。
- 精度验收：对独立 FP32 参考 err ≤ 4.5%·max|ref|、calc_diff ≤ 1e-3；shared 真实权重的误差 ≤ 模型参考的 1.5 倍。
- shared 权重：收 FP4PTPC 的每行 F32 scale 或官方 32×32 E8M0 块（prepare 折叠，与 FP4PTPC@97cc9b32 逐字节同）；@main 的 MTP 有损，MTP 用块格式。
- 不做：同目录的 FP8 / BF16 底座；EP / expert_mask、bias、SiLU 以外的激活、预量化输入、gfx950、非 MXFP4 的 Qwen shared；经 fused_moe 时这些与指定 tile 报错。

## 2. 总体设计
<!-- ≤35 行：数据流图（≤12 行）；分档表；每个核心 kernel ≤8 行伪代码（tile 划分与流水线的骨架，不写寄存器与偏移）。 -->
权重经 LUT 解成 fp8 走 fp8 MFMA；激活按行量化（与参考逐位一致）；按 M 与每 expert 行数分四档，排序只用 prep；shared 只有混合与折叠两种；骨架见下，全文见 [kernels.md](kernels.md)。
```text
加载时 prepare_moe_a8w4_ptpc_weight：mxfp4 → 私有布局（按 MFMA K 序排的 fp4、每 32-K 组 delta、每通道因子），I 补零到 64 的倍数
  [shared FP8：块 scale 先折叠成每行 2 的幂 → e4m3fn 转 fnuz（scale ×2）→ I 补零 → shuffle(16,16)，作 expert E]
aiter.fused_moe(x, w.w1, w.w2, …, Silu, per_1x32, per_Token)：首行见 w1 / w2 的标记 → _fused_moe_route（门禁、配对、查参数）→ ↓
flydsl_moe_a8w4_ptpc（bf16 x[M,H] → bf16 out[M,H]；无 host 同步，可被 graph 捕获；out 未 4 B 对齐时写对齐缓冲再拷回）：
  decode：[行量化(x)] → Gate/Up decode（WG 管一条路由）→ mid f32 → [行量化(mid) → 槽对版] Down decode（WG 管一个 token）→ out
    混合（带 shared、M·topk·I ≤ 10368）：同两个 kernel 的 SHARED 变体，shared 作末路（FP8 直读；GU 每通道块 2 WG，Down 末 wave）
  H5120 去重（M8–10）：计划 + 行量化(x) → Gate/Up 去重（组首 WG 算同 expert 的 2 条路由）→ 行量化(mid) → 槽对 Down → out
  流式：prep（排序成 16 / 32 / 64 行的块 + 一行一 wave 量化 x + 清零 out）→ Gate/Up 流式 → [行量化(mid)] → Down 流式原子加进 out
  prefill：prep（64 行的块，不清零；≤64 个排序 WG，路由多时每个按段处理）→ Gate/Up prefill（gather xq 行）→ mid f32 → 行量化(mid)
    → Down prefill（× 通道因子 × ms × 路由权重，写 loc_ids）→ routes bf16 → route_sum（64 位寻址，可超 4 GiB）→ out
  折叠（带 shared 的其余调用）：routed 跳过末列；shared GU GEMM(xq，每块 ≤ 65536 行) → shared_mid（SiLU(L)·up、行量化、× 权重；M > 512 每行 8/16 lane）
    → shared Down → 写 out（槽对 / 原子 Down 加在其上；未 16 B 对齐时经临时缓冲拷入）或 routes 末尾 M 行；prefill 档外在侧流
```
| 输入范围 | 路径 | 为什么 |
|---|---|---|
| H<4096 且 GU 网格 < 2560 WG；H5120 到 M10；其余到 M7 | decode（Down 放不下改流式） | 填充为主（M1 快 2.6–5.8 倍）；上限外流式 graph 省 4–23% |
| （decode）H<4096 或 5120、M ≥ 4 或 topk > 16、w2 ≤ 4 GiB | 先量化 mid，Down 用槽对版 | 16 B 读两槽；H4096 用核内量化版省 3–16% |
| （decode）H5120、I%128≠0、M8–10 | 只去重 Gate/Up（组 2），Down 用槽对版 | I576 非 128 倍数；M8 比逐路由快 1.5% |
| decode 档外，每 expert ≤44 行（H≥4096、I<512 为 256；I>960 为 28） | 流式：排序块 16（≤12 行）/ 32（≤28）/ 64 | 读权重为主；上限内比 prefill 快 2–7% |
| （流式）BM ≥ 32、H < 4096 且累加器 ≤ 96 VGPR（H2560 BM64 到 56 行） | Gate/Up 一个 WG 管全部 I、尾部量化 | 省一次行量化；H4096 时轻 wave 更快 |
| （流式 Down）一律；块 64、I 512–960 用 8 wave | bf16x2 原子加进 prep 清零的 out | 免 routes 读写与求和；8 wave 每 SIMD 2 wave，快 9–16% |
| （H5120）流式路由 ≥ 4096；prefill 路由 ≥ 16384 | 流式上限 24 行；按 XCD 分块 | 17–24 行流式快 3–8%，28 行起 prefill 快；XCD 快 1–4% |
| （prefill）H5120、E ≥ 256、路由 ≥ 98304、默认 tile | Gate/Up 每 CU 3 WG、XCD 分块 2、x 提前 2 | 每 XCD 在算的 tile 少，权重留 L2；GU 快 6–15% |
| 其余 M；给了 tile 参数 | prefill BM64·BN128，行多 TK128；BM·I_pad > 64 KiB：给参数报错，不给走流式 | 多行共用权重；TK128 的 LDS 与寄存器减半 |
| （prefill）一律（任意 H、M） | 排序与 x 量化也用 prep（一次 launch） | M4096 前端比 Opus + 行量化快 1.6–2.5 倍 |
| （prefill）I ≥ 256 且排序块少；I > 512 且 WG > 80 | Down 的 H 切给 2 / 4 个 WG；激活分两段 | 末轮少空闲（M2048 快 10%）；每 CU 2 WG |
| 带 shared：decode 档、M ≤ 10、M·topk·I ≤ 10368、≤ 16 列 | 混合：shared 作末路 | 不另起 kernel；MTP TP8 M5 为折叠的 0.63 |
| 带 shared 的其余调用（decode 档一律槽对 Down，用不了时改流式） | 折叠进末次规约，GEMM 按 65536 行分块；prefill 档不用侧流 | 省 x 量化与相加；÷ split ≤ 0.998 |
| （折叠）每块 M ≥ 769（I ≤ 384）/ 8192（I576） | shared Down 自写：权重作 A、16 B 写回藏进下一对 MFMA | 只读真实 K；整层快至 4% |
- 屏蔽（id −1，ATOM 的 padding 行）：decode 经越界 buffer 视图读 0（不访存）、Down 用 select 丢弃，去重计划与排序不收；首列 −1 或末列非 E 时 shared 也丢。
- decode：Gate/Up 每 WG 管一条路由的 16 通道（去重时组首连算组员），lane 16 B 读两个 64-K 块；Down 每 WG 管一个 token 的 32 通道、每列一 wave（≤16 列；槽对版 16）
- 流式：Gate/Up 每 wave 管 G 对 gate / up 块，权重直读 VGPR（每 expert 满一块行时缓存读）、提前 P 步，激活经 LDS 环共享；Down 激活留 VGPR / LDS，权重提前 1–2 对
- prefill：Gate/Up 4 wave 管 TILE_M 行 × 64 gate + 64 up，权重提前 2 tile、x 经 LDS 双缓冲；Down 的 mq 驻留 VGPR，逐 64 列块写 routes

## 3. 关键决策
<!-- 3–6 条；“为什么”给一个关键数字。 -->
routed 输出除原子加（容差内）外与 M17 逐位相同（只改读取宽度、解码、量化与预取）；shared 小工作量时并进 decode，其余复用 xq、折进末次规约。
| 决策 | 备选 | 为什么 | 代价 / 限制 |
|---|---|---|---|
| fp4 按 MFMA K 序预排；每 lane 读 16 B | 解成 bf16；8 B 读 | 流式读指令 226→126；decode VGPR 153→87 | prefill Down 仍 8 B；delta>11 按 0 |
| 排序只用自写 prep（排序与量化 x 一次 launch，排序 WG ≤ 64） | Opus 排序 + 行量化 | M4096 前端快 1.6–2.5 倍 | 块内顺序不定（结果不变）；大 M 比纯量化多 15–20% |
| 行量化商逐位等于 IEEE 除法，每行一次倒数 + FMA 修正 | 乘倒数不修正；逐值除法 | 不翻转量化；逐值除法约占 decode wave 1/3 VALU | 极端行逐值除 |
| decode 档不排序、按 GU 网格划界；行少时小块流式、原子 Down | 全走 BM64；按 M 划界；MiMo 去重 | BM64 在 M128 时约 95% 是填充 | 四套 kernel；原子加不逐位确定 |
| fused_moe 按 w1 / w2 的标记转调，tile 自动 | 内部转换缓存；按 block_size_M 钉 tile | 内部转换要双份权重；钉 tile 时 DS M=1 慢 3.5 倍 | 标记是 Python 属性 |
| shared 作 expert E：混合（decode 的 SHARED 版）或折叠（大 M 自写 Down） | split 后相加；按 M 划界 | 省量化与相加；混合 wave 随 topk·I 增 | 末列；未对齐多拷贝一次 |

## 6. 风险与待定
<!-- ≤5 条：风险 → 影响 → 打算。 -->
测量噪声比逐例 1.02 线还大（同代码臂同卡交替差到 3.9%，混合 M4 例 graph 双峰），逐例按多轮中位数判；差距拆解见第 4 节。
- 测量：450 TF 即 PTL 下 FP8 的持续上限（短时 577、降频 410 TF），层内 kernel 比隔离慢 0–25%；reset 后 PTL 变 Disabled、他人占卡 → 门禁拒绝。
- 固定开销：每 kernel ≥2.3–3 µs，decode M ≤ 2 占 45–65%、行量化几乎全是它；fork/join 层内中位 4–5 µs → 少 kernel、少跨流只能靠合并。
- shared 链与接口：自写 Down 大 M 仍是 ① 的 1.4–1.5×（VMEM 发射、层内功耗态）；GEMM 偶发 LDS 块错（已限 tile）；fused_moe 认 Python 属性；登记开关非线程安全。
- 未对齐输出：2 B 偏移的 output（含原地）整次写对齐缓冲再拷回 → 多一个拷贝 kernel（读写 4·M·H B）→ 少见调用，不再优化。
