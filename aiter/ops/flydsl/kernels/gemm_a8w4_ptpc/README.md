## 1. 目标与范围
在 MI308X（gfx942）上做 dense GEMM Y = X·Wᵀ：bf16 X 按 token 动态量化成 fp8 e4m3fnuz，W 为 mxfp4，fp32 累加，输出 bf16。
- 输入：x bf16 [M, K]（任意 M、连续）；权重为 checkpoint 的 mxfp4（fp4x2 [N, K/2] + E8M0 [N, K/32]），加载时转换一次。
- 形状：Qwen3.8-Flash-Next dense 线性层 TP2 / TP4 的 6 个 (N, K)（N 2560–8192，K 1536–3072）× M = 1…32768。
- 约束：K % 256 == 0、N % 64 == 0、权重 < 2 GiB，其他形状与非 gfx942 明确报错；无 host 同步，可被 CUDA graph 捕获。
- 验收：每 case 耗时 ≤ 1.05× 同一 aiter 的 fp8 ptpc GEMM，M ≤ 32 时 ≤ 0.7×；M > 2048 达到 compute bound：≥ 453 TFLOPS 且不慢于对照（第 4 节）。
- 精度：对照测试文件内的独立 fp32 参考，逐元素按行 1% 容差（第 4 节）。
- 不做：bias、fp16 输出、已量化输入的接口、gfx950 / gfx1250、W4A16。

## 2. 总体设计
权重在寄存器里按每组 LUT 解成 fp8、走 fp8 MFMA；M ≤ 32 一个 kernel 在 CTA 内量化 X 并算完，更大的 M 先量化再 GEMM。
```text
加载时 prepare_gemm_a8w4_ptpc_weight：mxfp4 → fd2 布局（按 MFMA K 序排的 fp4 码、每 32-K 组 delta、每通道因子）
flydsl_gemm_a8w4_ptpc(x, weight, out=None)（无 host 同步）：
  M ≤ 32（一次 launch）：decode 或 tile：x bf16 在 CTA 内按 token 量化进 LDS，乘 fd2 权重 → y bf16 [M, N]
  其余（两次 launch）：quant_x：x bf16 [M, K] → xq fp8 [M, K] + xs f32 [M]（scale = amax/240，商逐位等于 IEEE 除法）
    gemm 或 gemm_large（按下表分派）：xq、xs、fd2 权重 → y bf16 [M, N] = acc · 通道因子 · xs
```
| 输入范围 | 路径 | 为什么 |
|---|---|---|
| M ≤ 8，K % 512 == 0 | decode（块对映射） | MFMA 不空半边，权重 16 B 一读 |
| 9 ≤ M ≤ 32，K % 512 == 0、LDS 放得下 | tile（16-token 片） | M > 8 时块对映射的 MFMA 翻倍 |
| 33–2048，及其他档不接的形状 | quant_x → gemm（64×128 tile） | tile 小、CTA 多，中小 M 也能铺开 |
| M > 2048 且 N % 256 == 0、K ≥ 512 | quant_x → gemm_large（持久化） | tile 数 ≥ 2 倍 CU，值得常驻流水 |
| M = 0 | 不启动 kernel | 输出为空 |

核心 kernel 骨架（完整的任务划分与逐拍流水线见 [kernels.md](kernels.md)）：
```text
decode / tile（M ≤ 32）：grid = 查表的 CTA 数（目标形状 52–128），CTA 管连续 ≤ rb 个 16 行块；rb·ks 个 wave = 行块槽 × K 段
  不流水：wave 先发完全部 x、delta、权重读；CTA 内量化 token 行（同 quant_x 的 amax 与商）→ fp8 写 LDS → barrier
  decode：每 lane 一条 16 B 读两个 64-K 块；x 作 A（8 token 占行 t 与 8+t），w 作 B；lane l 与 l^40 的两个 K 半段相加
  tile：w 作 A（16 通道）、16-token 片作 B；K 分 kp 个窗口逐个量化进 LDS，让 32 行 fp8 装得下
  收尾：K 段部分和经 LDS 按段号顺序相加（不跨 CTA 切 K）→ × 通道因子 × xs → bf16；≥ M 的 token 不写
quant_x：每行 L 个 lane（K % 512 == 0 时 64，否则 32），CTA 256 线程管 256/L 行
  lane 第 v 次 16 B 读行内第 sub + v·L 个 16 B 单元（一条指令读连续 16·L B），8 B 写同样交错
  amax = bf16 位模式去符号后的无符号 max（与 |x| 同序，NaN 照常传播）→ scale → 量化
gemm：grid (⌈N/128⌉, ⌈M/64⌉)，4 wave 管 64 token × 128 通道（每 wave 两个 16 通道块，全部 64 token）
  xq tile 经 LDS 双缓冲，fd2 权重直读 VGPR，两者都提前 1 个 K tile（128 K）预取
  每 128-K 步每 lane 建一个 LUT → fp4 解码成 fp8 → MFMA 16x16x32（解码与 LDS 读排进 MFMA 之间）
  收尾：acc × 通道因子 × xs → bf16；≥ M 的行由 buffer 边界丢弃，≥ N 的通道跳过
gemm_large：grid = min(tile 数, CU 数)，CTA c 依次做 tile c, c+G, …；tile = 128 token × 256 通道
  8 wave 分两组（每 SIMD 各一个），wave w 管 32 个通道 × 128 token；每个 128-K 步分搬运相与计算相
  两组错开一相交替：一组发 64 条 MFMA（解码 VALU 交织其间），另一组读写 LDS、发后两步的 VMEM
  X 经 LDS 双缓冲、提前 2 步加载；W 直读 VGPR 两槽，每半步一条 16 B；跨 tile 不排空，每相一次 barrier
  收尾放在 tile 最后一步的计算相：MFMA 按 token 块两两跑，穿插上一对块的缩放、bf16 舍入与 16 B 写
```

## 3. 关键决策
fp4 在寄存器里解成 fp8 走 fp8 MFMA；小 M 把量化融进一次 launch，大 M 换持久化大 tile 核、两组 wave 一算一搬。
| 决策 | 备选 | 为什么 | 代价 / 限制 |
|---|---|---|---|
| fp4 解成 fp8，走 fp8 MFMA | 解成 bf16 走 bf16 MFMA | 无 fp4 MFMA；fp8 算力为 bf16 的 2 倍 | 激活须量化成 fp8 |
| fd2：组 delta 进 LUT，通道因子收尾乘 | 每组 E8M0 现场乘 | 每 8 个码解码只要 2 次 v_perm | delta ≥ 12 的组置 0 |
| M ≤ 32 在 CTA 内量化，更大 M 单独量化 | 都单独量化（两次 launch） | 小 M 单独量化占 3–5 µs，对照共约 10 µs | 每 CTA 重复量化，故不跨 CTA 切 K |
| M ≤ 8 块对映射，9–32 标准映射 | 一种映射覆盖 M ≤ 32 | ≤ 8 时块对不空转，> 8 时其 MFMA 翻倍 | 两个小 M 核；配置按形状查表 |
| M > 2048 另用持久化 128×256 核 | 一个 tile 配置覆盖所有 M | 大 tile 摊薄解码；跨 tile 不排空 | 两个 GEMM 核；N % 256、K ≥ 512 才能用 |
| 大 M 两组 wave ping-pong | CK 式单组流水线 | W 的 VMEM 条数是瓶颈；大 M 338→432 TF | 用满 256 VGPR，每 CU 1 个 CTA |

## 4. 性能与精度
现状：96 个 case 输出都正确；M ≤ 8 全部快于对照（13 例 ≤ 0.7×）；M 16–2048 多数仍慢于对照；大 M 全部快于对照、4 例达 453 TF。
| M（6 形状） | 本实现 ÷ 对照（几何均值，范围） | 本实现（几何均值） | 对照（几何均值） | 结论 |
|---|---|---|---|---|
| 1–8 | 0.69×（0.54–0.91） | 0.80 TB/s（峰值 15%） | 1.04 TB/s（20%） | 解码 VALU 限速，离访存上限远 |
| 16–32 | 1.08×（0.78–1.45） | 0.52 TB/s（9.7%） | 1.02 TB/s（19%） | 量化、解码与 x 到达串行 |

| 4096–32768 | 0.87×（0.80–0.92） | 432 TFLOPS（71%） | 378 TFLOPS（62%） | 持久化核；未全达 453 TF |
- 上表取自下方 mf 生成块（同卡配对复核）；TB/s 按各自最小数据量，峰值 5.3 TB/s、606 TFLOPS。
- 453 TF = 同卡实测 fp8 MFMA burst 峰值 565.8 TF 的 80%（持续上限约 465 TF）；计时含量化 kernel。
- 对照：同一 worktree（aiter 上游 main `162173e89`）的 fp8 ptpc，即 `per_token_quant_hip(x, fp8)` + `gemm_a8w8_bpreshuffle`，
  与 SGLang gfx942 `apply_fp8_ptpc_linear` 的调用一致；权重 = 同一份 mxfp4 精确反量化（含置 0 规则）后按通道量化成 fp8。
- 对照选中的 kernel：TP2 三个形状命中调优表的 CK kernel（tp2_o 的 M32768 用默认），TP4 全部用默认 CK；bench 逐 case 打印。
- 计时：两边同进程、逐 case 交替、同协议（aiter `run_perftest`，输入深拷贝轮换，一次调用的全部 kernel 时间相加）。
- 已知计时偏差：空闲后访存时钟约 5 ms 才升回，中间档每 case 计时约 6 ms，偶有开头慢段未被 IQR 去掉 → 之后 bench 加约 12 ms 预热、重新冻结。
- 精度参考：测试文件内独立 fp32 参考（X 同一量化点，W 精确反量化并施加同一置 0 规则，fp32 matmul，关 TF32）。
- 判据：逐元素 |Y−ref| ≤ 1%·|ref| + 1%·该行 max|ref|，calc_diff ≤ 1e-5，无 NaN/Inf；对照用它自己的量化操作数按同一判据校验。

- 权重接近 2 GiB 上限时的正确性：目标权重最大 10.5 MB，这样的 prepare 要十几 GB 显存；只测了拒绝一侧。
- ±Inf 行的 fp8 码：quant_x 与小 M 核都整行写 NaN 码，torch 的有限元素为 0；两边输出都是整行 NaN，用例只比 scale 与输出。
- 大 M 核按实际 CU 数开 grid、小 M 配置表按 80 CU 定：只在 80 CU 的 MI308X 上跑过；用例按实际 CU 数构造形状。
- decode 核 LDS 超 64 KB 的形状（如 M 5–8 且 K ≥ 7168）launch 失败：已知问题（第 6 节），没有用例。

## 6. 风险与待定
- 小 M 只有 13/36 例 ≤ 0.7×（M 16–32 为 0.78–1.45×）：解码 VALU、每 CTA 重复量化、x 晚到被 barrier 串行 → 小 M 第二轮里程碑换结构（下界约 0.6×）。
- 小 M 分派不查 decode 核的 LDS：K 大时（如 M 5–8 且 K ≥ 7168）超 64 KB、launch 失败（目标形状不受影响）→ 分派补 LDS 检查。
- 中间档（64–2048）为对照的 0.93–2.5 倍，M ≤ 128 最慢；分派门限 2048 未按形状调 → 中间档里程碑按 M 选 tile、重定门限。
- 大 M 20 例低于 453 TF（377–451）：量化另起、末轮 tile 填不满 CU、收尾未与 MFMA 重叠 → 后续里程碑；核已用满 256 VGPR，改前先读流水线规则。
- delta ≥ 12 的组置 0：组 scale 不到通道最大的 2⁻¹¹，真实权重少见；出现时有精度损失（参考施加同一规则）。
