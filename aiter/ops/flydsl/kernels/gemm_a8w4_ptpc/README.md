## 1. 目标与范围
在 MI308X（gfx942）上做 dense GEMM Y = X·Wᵀ：bf16 X 按 token 动态量化成 fp8 e4m3fnuz，W 为 mxfp4，fp32 累加，输出 bf16。
- 输入：x bf16 [M, K]（任意 M、连续）；权重为 checkpoint 的 mxfp4（fp4x2 [N, K/2] + E8M0 [N, K/32]），加载时转换一次。
- 形状：Qwen3.8-Flash-Next dense 线性层 TP2 / TP4 的 6 个 (N, K)（N 2560–8192，K 1536–3072）× M = 1…32768。
- 约束：K % 256 == 0、N % 64 == 0、权重 < 2 GiB，其他形状与非 gfx942 明确报错；无 host 同步，可被 CUDA graph 捕获。
- 验收：每 case 耗时 ≤ 1.05× 同一 aiter 的 fp8 ptpc GEMM，M ≤ 32 时 ≤ 0.7×；M > 2048 达到 compute bound：≥ 453 TFLOPS 且不慢于对照（第 4 节）。
- 精度：对照测试文件内的独立 fp32 参考，逐元素按行 1% 容差（第 4 节）。
- 不做：bias、fp16 输出、已量化输入的接口、gfx950 / gfx1250、W4A16。

## 2. 总体设计
权重在寄存器里按每组 LUT 解成 fp8、走 fp8 MFMA；先量化 X，再按 M 分两档：M ≤ 2048 用通用 GEMM，M > 2048 用持久化 GEMM。
```text
加载时 prepare_gemm_a8w4_ptpc_weight：mxfp4 → fd2 布局（按 MFMA K 序排的 fp4 码、每 32-K 组 delta、每通道因子）
flydsl_gemm_a8w4_ptpc(x, weight, out=None)（无 host 同步，两次 launch）：
  quant_x：x bf16 [M, K] → xq fp8 [M, K] + xs f32 [M]（scale = amax/240，商逐位等于 IEEE 除法）
  gemm 或 gemm_large（按下表分派）：xq、xs、fd2 权重 → y bf16 [M, N] = acc · 通道因子 · xs
```
| 输入范围 | 路径 | 为什么 |
|---|---|---|
| M ≤ 2048，或 N % 256 ≠ 0，或 K = 256 | quant_x → gemm（64×128 tile） | tile 小、CTA 多，中小 M 也能铺开 |
| M > 2048 且 N % 256 == 0、K ≥ 512 | quant_x → gemm_large（128×256，持久化） | 目标形状 tile 数 ≥ 2 倍 CU，值得常驻流水 |
| M = 0 | 不启动 kernel | 输出为空 |

核心 kernel 骨架（完整的任务划分与逐拍流水线见 [kernels.md](kernels.md)）：
```text
quant_x：每行 L 个 lane（K % 512 == 0 时 64，否则 32），CTA 256 线程管 256/L 行
  lane 第 v 次 16 B 读行内第 sub + v·L 个 16 B 单元（一条指令读连续 16·L B），8 B 写同样交错
  amax = bf16 位模式去符号后的无符号 max（与 |x| 同序，NaN 照常传播）→ scale → 量化
gemm：grid (⌈N/128⌉, ⌈M/64⌉)，4 wave 管 64 token × 128 通道（每 wave 两个 16 通道块，全部 64 token）
  xq tile 经 LDS 双缓冲，fd2 权重直读 VGPR，两者都提前 1 个 K tile（128 K）预取
  每 128-K 步每 lane 建一个 LUT → fp4 解码成 fp8 → MFMA 16x16x32（解码与 LDS 读排进 MFMA 之间）
  收尾：acc × 通道因子 × xs → bf16；≥ M 的行由 buffer 边界丢弃，≥ N 的通道跳过
gemm_large：grid = min(tile 数, CU 数)，CTA c 依次做 tile c, c+G, …；tile = 128 token × 256 通道
  8 wave 分两组（每 SIMD 各一个），wave w 管 32 个通道 × 128 token；每个 128-K 步分搬运相与计算相
  两组错开一相交替：一组发 64 条 MFMA（解码 VALU 交织其间），另一组读写 LDS、发后两步的 VMEM
  X 经 LDS 双缓冲、提前 2 步加载；W 直读 VGPR 两槽，每半步一条 16 B；跨 tile 不排空，每相一次 barrier
  收尾放在 tile 最后一步的计算相：MFMA 按 token 块两两跑，穿插上一对块的缩放、bf16 舍入与 16 B 写
```

## 3. 关键决策
fp4 在寄存器里解成 fp8 走 fp8 MFMA；大 M 换持久化大 tile 核，两组 wave 一算一搬，计算 wave 只发 MFMA 与解码。
| 决策 | 备选 | 为什么 | 代价 / 限制 |
|---|---|---|---|
| fp4 解成 fp8，走 fp8 MFMA | 解成 bf16 走 bf16 MFMA | 无 fp4 MFMA；fp8 算力为 bf16 的 2 倍 | 激活须量化成 fp8 |
| fd2：组 delta 进 LUT，通道因子收尾乘 | 每组 E8M0 现场乘 | 每 8 个码解码只要 2 次 v_perm | delta ≥ 12 的组置 0 |
| 先量化 X 再 GEMM（两个 kernel） | GEMM 内量化 | 量化可逐位校验，GEMM 不背量化的寄存器 | 多一次启动与 xq 读写，大 M 也可见 |
| M > 2048 另用持久化 128×256 核 | 一个 tile 配置覆盖所有 M | 大 tile 摊薄解码；跨 tile 不排空 | 两个 GEMM 核；N % 256、K ≥ 512 才能用 |
| 大 M 两组 wave ping-pong | CK 式单组流水线 | W 的 VMEM 条数是瓶颈；大 M 338→432 TF | 用满 256 VGPR，每 CU 1 个 CTA |
| 每个 CTA / tile 把 buffer 基址移到首行 | 全局 32 位偏移 | 任意 M 不溢出；越界行读 0、写丢弃 | 无 |

- 453 TF = 同卡实测 fp8 MFMA burst 峰值 565.8 TF 的 80%（持续上限约 465 TF）；计时含量化 kernel。
- 对照：同一 worktree（aiter 上游 main `162173e89`）的 fp8 ptpc，即 `per_token_quant_hip(x, fp8)` + `gemm_a8w8_bpreshuffle`，

## 6. 风险与待定
- 小 M（≤ 32）为对照的 1.8–3.1 倍（目标 ≤ 0.7×）：只有 N/128 个 CTA、无 split-K、量化单独启动 → 小 M 里程碑做融合量化与 split-K。
- 中间档（64–2048）为对照的 0.93–2.5 倍，M ≤ 128 最慢；分派门限 2048 未按形状调 → 中间档里程碑按 M 选 tile、重定门限。
- 大 M 20 例低于 453 TF（378–451）：量化另起 kernel、末轮 tile 填不满 CU、收尾 VALU 未与 MFMA 重叠 → 后续里程碑融合量化、末轮 split-K。
- 大 M 核用满 256 VGPR、每 CU 一个 CTA：加寄存器就会 spill 或降占用；改之前先读 gemm_large.py 的流水线规则。
- delta ≥ 12 的组置 0：组 scale 不到通道最大的 2⁻¹¹，真实权重少见；出现时有精度损失（参考施加同一规则）。
