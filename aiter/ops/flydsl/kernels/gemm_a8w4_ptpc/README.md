## 1. 目标与范围
在 MI308X（gfx942）上做 dense GEMM Y = X·Wᵀ：bf16 X 按 token 动态量化成 fp8 e4m3fnuz，W 为 mxfp4，fp32 累加，输出 bf16。
- 输入：x bf16 [M, K]（任意 M、连续）；权重为 checkpoint 的 mxfp4（fp4x2 [N, K/2] + E8M0 [N, K/32]），加载时转换一次。
- 形状：Qwen3.8-Flash-Next dense 线性层 TP2 / TP4 的 6 个 (N, K)（N 2560–8192，K 1536–3072）× M = 1…32768。
- 约束：K % 256 == 0、N % 64 == 0、权重 < 2 GiB，其他形状与非 gfx942 明确报错；无 host 同步，可被 CUDA graph 捕获。
- 验收：每 case 耗时 ≤ 1.05× 同一 aiter 的 fp8 ptpc GEMM，M ≤ 32 时 ≤ 0.7×；M > 2048 达到 compute bound：≥ 453 TFLOPS 且不慢于对照（第 4 节）。
- 精度：对照测试文件内的独立 fp32 参考，逐元素按行 1% 容差（第 4 节）。
- 不做：bias、fp16 输出、已量化输入的接口、gfx950 / gfx1250、W4A16。

## 2. 总体设计
权重在寄存器里按每组 LUT 解成 fp8、走 fp8 MFMA；按 (N, K) × M 档分派：小 M 一个 kernel 在 CTA 内量化 X 并算完，其余先量化再 GEMM。
```text
加载时 prepare_gemm_a8w4_ptpc_weight：mxfp4 → fd2 布局（按 MFMA K 序排的 fp4 码、每 32-K 组 delta、每通道因子）
flydsl_gemm_a8w4_ptpc(x, weight, out=None)（无 host 同步）：
  小 M（一次 launch）：dec2、decode 或 tile：x bf16 在 CTA 内按 token 量化进 LDS，乘 fd2 权重 → y bf16 [M, N]
  其余（两次 launch）：quant_x：x bf16 [M, K] → xq fp8 [M, K] + xs f32 [M]（scale = amax/240，商逐位等于 IEEE 除法）
    gemm（按表选 tile）或 gemm_large：xq、xs、fd2 权重 → y bf16 [M, N] = acc · 通道因子 · xs
```
| 目标形状的 M | 路径 | 为什么 |
|---|---|---|
| tp2_qkvz 1–2，tp2_qkv 1–4 | dec2（decode 分角色） | x 先到，权重 wave 不等 barrier |
| 其余 1–8 | decode（块对映射） | MFMA 不空半边，权重 16 B 一读 |
| 9–16（tp4_o 9–20） | tile（16-token 片） | M > 8 时块对映射的 MFMA 翻倍 |
| 之上到 128 / 512 / 1024（按形状） | quant_x → gemm（按 M 档查表选 tile） | 小 tile、K 组让 CTA 铺满 CU |
| 更大的 M | quant_x → gemm_large（持久化） | 实测 tile 够多时持久化核更快 |
| M = 0 | 不启动 kernel | 输出为空 |

- gemm 档止于 M = 128（tp2_qkvz）、512（tp2_qkv、tp4_qkvz）、1024（其余）；表外形状：小 M 核到 32，gemm 到 2048。
- 核用不了就退到下一个：小 M 核要 K % 512 == 0、LDS ≤ 64 KiB（dec2 → decode → tile → gemm）；gemm_large 要 N % 256 == 0、K ≥ 512。

核心 kernel 骨架（完整的任务划分与逐拍流水线见 [kernels.md](kernels.md)）：
```text
decode / dec2 / tile（小 M）：grid = 按 N 选的 CTA 数（目标形状 52–128），CTA 管连续 ≤ rb 个 16 行块；rb·ks 个 wave = 行块槽 × K 段
  不流水：wave 先发完全部 x、delta、权重读；CTA 内量化 token 行（同 quant_x 的 amax 与商）→ fp8 写 LDS → barrier
  decode：每 lane 一条 16 B 读两个 64-K 块；x 作 A（8 token 占行 t 与 8+t），w 作 B；lane l 与 l^40 的两个 K 半段相加
  dec2：同 decode 映射、每 CU 一个 CTA；另 mcap 个 wave 只量化 x、搬 delta，经 LDS 计数器发布，权重 wave 只等计数器
  tile：w 作 A（16 通道）、16-token 片作 B；K 分 kp 个窗口逐个量化进 LDS，让 32 行 fp8 装得下
  收尾：K 段部分和经 LDS 按段号顺序相加（不跨 CTA 切 K）→ × 通道因子 × xs → bf16；≥ M 的 token 不写
quant_x：每行 L 个 lane（K % 512 == 0 时 64，否则 32），CTA 256 线程管 256/L 行
  lane 第 v 次 16 B 读行内第 sub + v·L 个 16 B 单元（一条指令读连续 16·L B），8 B 写同样交错
  amax = bf16 位模式去符号后的无符号 max（与 |x| 同序，NaN 照常传播）→ scale → 量化
gemm（配置 GemmConfig）：1-D grid，CTA = kg 组 × 4 wave，管 BM token × BN 通道（BM 16–64，BN 64 / 128）
  CTA 按 XCD 轮流派发：超块 = xcd_m 个 M 块 × 4/xcd_m 个 N 块；xcd_m = 4 时一个 X 块只进一个 XCD 的 L2
  K 分 kg 段；每段 xq tile 经 LDS 双缓冲（提前 XS 个 tile 进 VGPR 暂存），fd2 权重直读 VGPR（提前 P 个 tile）
  每 TK（128 / 256）K 一阶段、一次 barrier：每 128 K 每 lane 建一个 LUT → fp4 解成 fp8 → MFMA 16x16x32
  K 组的部分和经 LDS 按固定顺序两两相加；收尾：acc × 通道因子 × xs → bf16；≥ M 的行丢弃、≥ N 的通道跳过
gemm_large：grid = min(tile 数, CU 数)，CTA c 依次做 tile c, c+G, …；tile = 128 token × 256 通道
  8 wave 分两组（每 SIMD 各一个），wave w 管 32 个通道 × 128 token；每个 128-K 步分搬运相与计算相
  两组错开一相交替：一组发 64 条 MFMA（解码 VALU 交织其间），另一组读写 LDS、发后两步的 VMEM
  X 经 LDS 双缓冲、提前 2 步加载；W 直读 VGPR 两槽，每半步一条 16 B；跨 tile 不排空，每相一次 barrier
  收尾放在 tile 最后一步的计算相：MFMA 按 token 块两两跑，穿插上一对块的缩放、bf16 舍入与 16 B 写
```

## 3. 关键决策
fp4 在寄存器里解成 fp8 走 fp8 MFMA；小 M 把量化融进一次 launch，中间档按形状查表选 tile，大 M 换持久化核。
| 决策 | 备选 | 为什么 | 代价 / 限制 |
|---|---|---|---|
| fp4 解成 fp8，走 fp8 MFMA | 解成 bf16 走 bf16 MFMA | 无 fp4 MFMA；fp8 算力为 bf16 的 2 倍 | 激活须量化成 fp8 |
| fd2：组 delta 进 LUT，通道因子收尾乘 | 每组 E8M0 现场乘 | 每 8 个码解码只要 2 次 v_perm | delta ≥ 12 的组置 0 |
| 小 M（≤ 16，tp4_o ≤ 20）在 CTA 内量化 | 都单独量化（两次 launch） | 小 M 单独量化占 3–5 µs，对照共约 10 µs | 每 CTA 重复量化；M 32 两核更快 |
| M ≤ 8 块对映射（最宽形状再分角色），之上标准映射 | 一种映射覆盖小 M | ≤ 8 时块对不空转；dec2 让 x 先到 | 三个小 M 核；配置按形状算 |
| 中间档按 (N, K) × M 档查表选 tile、K 组、XCD 超块 | 一个 64×128 tile | M 64–128 时 64×128 只有 20–64 个 CTA | 表只为目标形状实测；表外走通用回退 |
| 大 M 持久化 128×256 核，两组 wave ping-pong | 通用 tile；单组流水线 | W 的 VMEM 条数是瓶颈；338→432 TF | 用满 256 VGPR；要 N % 256、K ≥ 512 |

- 453 TF = 同卡实测 fp8 MFMA burst 峰值 565.8 TF 的 80%（持续上限约 465 TF）；计时含量化 kernel。
- 对照：同一 worktree（aiter 上游 main `162173e89`）的 fp8 ptpc，即 `per_token_quant_hip(x, fp8)` + `gemm_a8w8_bpreshuffle`，
  与 SGLang gfx942 `apply_fp8_ptpc_linear` 的调用一致；权重 = 同一份 mxfp4 精确反量化（含置 0 规则）后按通道量化成 fp8。
- 对照选中的 kernel：TP2 三个形状命中调优表的 CK kernel（tp2_o 的 M32768 用默认），TP4 全部用默认 CK；bench 逐 case 打印。
- 计时：两边同进程、逐 case 交替、同协议（aiter `run_perftest`：输入深拷贝轮换，一次调用的全部 kernel 时间相加，IQR 去离群后取均值）。
- 预热：两边每次计时前都按实测单次耗时补足 ≥约 12 ms 的调用——空闲后访存时钟约 5 ms 才升回，只预热 2 次时中间档偶尔读高 10–30%。
- 精度参考：测试文件内独立 fp32 参考（X 同一量化点，W 精确反量化，fp32 matmul，关 TF32）；它同样把 delta ≥ 12 的组置 0，此损失不计入判据（真实权重少见）。
- 判据：逐元素 |Y−ref| ≤ 1%·|ref| + 1%·该行 max|ref|，calc_diff ≤ 1e-5，无 NaN/Inf；对照用它自己的量化操作数按同一判据校验。

| 编译缓存：形状交替、回到旧形状、同名核不同 K | bench 每个形状只顺序访问一次 | `test_compile_cache` | 通过 |

未覆盖 / 跳过：
- 非 gfx942（只用替身模拟架构判断）与多 GPU（每卡一份编译句柄、x 与权重不同卡）：本机只有 gfx942，测试只用一张卡。
- 权重接近 2 GiB 上限时的正确性：目标权重最大 10.5 MB，这样的 prepare 要十几 GB 显存；只测了拒绝一侧。
- ±Inf 行的 fp8 码：quant_x 与小 M 核都整行写 NaN 码，torch 的有限元素为 0；两边输出都是整行 NaN，用例只比 scale 与输出。
- 大 M 核按实际 CU 数开 grid、小 M 配置与分派表按 80 CU 定：只在 80 CU 的 MI308X 上跑过；用例按实际 CU 数构造形状。
- tp4_qkvz 中间档→大核只钉两侧（M512 / M1025），确切换档点暂不钉：M513 只核对与预测一致，留给下一个调中间档表的里程碑钉回。
- gemm 档内换 tile 的 M（如 tp2_qkv 64/65 换 BM48）只由 bench 在 2 的幂处校验数值，不逐个核对 kernel：末行块截断与跨档同一机制。
- gemm 分派不选的配置（BM128、BN256、TK128 + K 组）与 compile 对超 LDS 配置的报错：分派不会走到，没有用例。
- bench 的预热是否够长：只影响离群率、不影响输出，要多次同卡 bench 统计才看得出，没有用例。

## 6. 风险与待定
- 小 M 17/36 例 ≤ 0.7×（M ≤ 8 宽形状 7 例 0.72–0.89×，M 16 为 0.77–1.06×，M 32 为 0.95–1.10×）：重复量化与解码 VALU 是下界 → 再降要 X 预排布局（未排期）。
- 中间档仍有 5 例慢于对照（TP2 的 M 64–128，1.03–1.17×）：同 tile 的 gemm 比 CK 慢约 15%，量化核比 aiter 慢 0.4–0.6 µs → 后续里程碑：量化核提速、gemm 对齐 CK。
- 分派表只为 6 个目标形状在 80 CU 的 MI308X 上实测：表外形状走通用回退（未调优），换卡要重测 → 新形状上线前补表项。
- 大 M 15 例低于 453 TF（388–452）：量化另起、末轮 tile 填不满 CU、收尾未与 MFMA 重叠 → 后续里程碑（L2 局部性、W 预取）；核已用满 256 VGPR，改前先读流水线规则。
- 计时残余噪声：aiter 小 M 开头慢段（约 ±4%，预热消不掉）；profiler 偶丢事件读出偏低错值 → 单次读数需复测，冻结 / 复核取多次中位 → 另做 bench 维护。
